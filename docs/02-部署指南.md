# 部署指南：从零把大肥鱼接进 QQ 群

> 本文以 **Windows 10/11** 为例，Linux 思路一致（文末有 systemd 示例）。
> NapCat 的界面和配置项会随版本变化，具体以 [官方文档](https://napcat.napneko.icu/) 为准。

---

## 0. 准备清单

| 需要 | 说明 |
| --- | --- |
| Python 3.10+ | 本项目在 3.14 上测试通过 |
| 一个 QQ 小号 | **强烈建议用小号**，第三方协议有封号风险；大号被冻结得不偿失 |
| [NapCatQQ](https://github.com/NapNeko/NapCatQQ) | 把 QQ 协议翻译成 OneBot v11 |
| [DeepSeek API Key](https://platform.deepseek.com/) | 注册后创建，账户里要有余额 |
| 能访问 `api.deepseek.com` 的网络 | 公司/校园网可能需要代理 |

心理准备：这不是官方接口。QQ 号有被风控甚至封禁的可能，频率越低越安全。

## 1. 装并登录 NapCat

### 1.1 下载

打开 [NapCatQQ Releases](https://github.com/NapNeko/NapCatQQ/releases)，Windows 用户一般选：

- `NapCat.Shell` 一键包（解压即用，推荐新手），或
- `NapCat.Framework` / 安装器（进阶）。

> 如果你的电脑上已经装了官方 NTQQ，也可以选对应版本；具体看 release 说明。

### 1.2 启动并扫码

1. 解压到一个**路径里没有空格和中文**的目录（比如 `D:\NapCat`）；
2. 双击 `launcher.bat` / `napcat.bat`（不同版本文件名不同）；
3. 按提示用 **QQ 小号** 扫码登录；
4. 启动日志里会出现 WebUI 地址和 token，类似：

```
WebUI: http://127.0.0.1:6099/webui
Token: xxxxxxxx
```

5. 浏览器打开 WebUI，粘贴 token 登录。

### 1.3 配置 OneBot v11 的 WebSocket 服务

在 WebUI 里找到「网络配置 / Network」：

1. 新建一个 **WebSocket 服务器**（正向 WebSocket Server）：
   - Host：`127.0.0.1`
   - Port：`3001`（本项目默认值）
   - Token：自己设一个（比如 `my-secret-token`），**记下来**
   - 启用
2. （可选）同一页把 HTTP 服务也开上，方便以后调试。
3. 保存后确认网络列表里该服务是「运行中」。

> 如果用的是 `LLOneBot` 或旧版 NapCat，配置入口类似：找「OneBot v11 / WebSocket 服务器」，端口与 token 一致即可。
> 如果 NapCat 与机器人不在同一台机器：把 Host 改成 `0.0.0.0`，机器人侧 `ws_url` 填对方 IP，并注意防火墙和 token。

### 1.4 自检

机器人启动后如果连不上，先在 PowerShell 里验证端口：

```powershell
Test-NetConnection 127.0.0.1 -Port 3001
```

`TcpTestSucceeded : True` 才说明服务在监听（不验证 token）。

## 3. 填配置

### 3.1 密钥

```powershell
Copy-Item .env.example .env
notepad .env
```

```dotenv
DEEPSEEK_API_KEY=sk-你的key
ONEBOT_ACCESS_TOKEN=my-secret-token
WEB_TOKEN=随便设一个访问密码
```

`ONEBOT_ACCESS_TOKEN` 必须和 NapCat 里 WebSocket 服务器填的 Token 完全一致；NapCat 那边没设就留空。
`WEB_TOKEN` 是 WebUI 的访问令牌，不用 WebUI 可留空；**要绑非本机地址时必须设**。

### 3.2 主配置

编辑 [config/config.yaml](../config/config.yaml)，最少改这几项：

```yaml
onebot:
  ws_url: ws://127.0.0.1:3001

chat:
  private:
    whitelist: [你的QQ号]   # 只让自己私聊，防止陌生人刷额度
  admin:
    qq: [你的QQ号]          # 管理命令
  group:
    wake_words: [大肥鱼, 肥鱼]
```

可选：

- `chat.filter.whitelist_groups`：只让机器人在自己人的群里工作，**上线初期强烈建议填**；
- `chat.group.ambient_chance: 0`：先关主动插话，观察一天再开；
- `persona.group_overrides`：给不同群绑定不同人格（例：`{123456789: config/persona-cat.md}`）；
- `deepseek.enable_tools: true`：让模型能调工具（时间 / 计算器 / 记笔记 / 查笔记），会多一轮请求；
- `metrics.enabled: true`（默认开）：记录 token / 耗时到 `data/metrics.db`，不存聊天内容。

### 3.3 人格

编辑 [config/persona.md](../config/persona.md)。这是 system prompt 的主体，怎么写见 [03-人格调教.md](03-人格调教.md)。多群人格配置见 [03-人格调教.md 5.1](03-人格调教.md#51-多群不同人格phase-31)。

### 3.4 图片理解（可选）

DeepSeek 的 chat 接口是纯文本的，要让它"看懂图"，需要再配一个 **OpenAI 兼容的视觉模型**（SiliconFlow、通义、OpenAI、本地 vLLM 都可以）。不配也能正常用，图片只会以 `[图片]` 占位。

1. 在 `.env` 填视觉模型的 key（和 DeepSeek 的 key 不是同一个）：

```dotenv
VISION_API_KEY=sk-你的视觉模型Key
```

2. 在 `config.yaml` 打开并填接口：

```yaml
vision:
  enabled: true
  base_url: https://api.siliconflow.cn/v1   # 一般要带 /v1
  model: Qwen/Qwen2.5-VL-32B-Instruct
  api_key_env: VISION_API_KEY
  max_images: 2
  cache_size: 50
```

3. 重启，日志应出现：`图片理解：Qwen/Qwen2.5-VL-32B-Instruct（https://...）`。
4. 群里 `@机器人` 发一张图并问"这是什么"，应能根据图片回答。

说明：

- 调用格式是 OpenAI 的 `chat/completions` + `image_url`（本项目会把图片下载后转成 base64 data URI）。
- 单张超过 `max_image_bytes`（默认 5MB）或类型不是 `image/*` 会被跳过并降级为 `[图片]`。
- 同一图片 URL 的描述会缓存（`cache_size` 条），避免重复花钱。
- `max_images` 控制每条消息最多识别几张图。
- 图片理解会增加 1~3 秒延迟，并产生独立的视觉模型费用；不需要时保持 `enabled: false`。

### 3.5 主动发言（可选，默认关闭）

无人说话时让机器人自己冒泡。**建议先观察群氛围再开**，只对明确列出的群生效：

```yaml
chat:
  proactive:
    enabled: true
    interval_minutes: 180      # 同群最小间隔
    quiet_start: 0             # 0~7 点不说话
    quiet_end: 7
    max_per_day: 3
    min_silence_minutes: 5     # 群里最近 5 分钟有人说话就不冒泡
    groups:
      123456789:               # 只对这个群生效
        interval_minutes: 240
        max_per_day: 2
        prompt: "提醒大家起来喝水，语气随意"
```

规则：

- 静默时段、最小间隔、每日上限、群安静守卫四道闸都满足才会调模型；
- 模型可以输出 `[PASS]` 表示"没话说"，此时不会发消息；
- 主动发的内容会写进群聊记忆和群背景，之后的对话能接上；
- 主动发言也会消耗一次模型调用（`[PASS]` 也算），别把间隔调很短。

### 3.6 WebUI（可选，默认关闭）

浏览器里看运行状态、会话消息、摘要和笔记，做临时静音、清空会话、运行时调参。

```yaml
web:
  enabled: true
  host: 127.0.0.1
  port: 8080
  token_env: WEB_TOKEN
```

启动后日志会打印 `WebUI：http://127.0.0.1:8080/`，浏览器打开：

- 右上角填 `.env` 里的 `WEB_TOKEN`，点「保存」（存 localStorage）；
- 「运行状态」看统计 / 模型 / 工具 / 图片理解 / 主动发言状态；
- 「用量（近 7 天）」看每天调用次数、token、平均耗时；
- 「会话」列表点进去看消息、摘要、笔记，可静音该群或清空会话；
- 「运行时开关」改主动插话概率、主动发言开关（**只改内存，重启恢复**；永久生效请改 config.yaml）。

安全：

- 默认只监听 `127.0.0.1`，外网访问请用反向代理 + HTTPS；
- 绑 `0.0.0.0` 但没配 `WEB_TOKEN` 时程序会拒绝启动 WebUI；
- 页面本身不含聊天数据，但 API 会返回聊天记录，token 不要外泄。

## 6. 后台常驻

### 6.1 Windows 计划任务（推荐）

1. 打开「任务计划程序」→ 创建任务；
2. 常规：勾选「不管用户是否登录都要运行」；
3. 触发器：登录时；
4. 操作：
   - 程序：`D:\蓝瑟大肥鱼\qq-deepseek-bot\.venv\Scripts\pythonw.exe`
   - 参数：`src\main.py`
   - 起始于：`D:\蓝瑟大肥鱼\qq-deepseek-bot`
5. 用 `pythonw.exe` 没有控制台窗口，日志需要重定向或改用 NSSM 之类的服务包装器。

调试阶段还是建议直接开一个 PowerShell 窗口跑，方便看日志。

### 6.2 Linux + systemd

```ini
# /etc/systemd/system/deepseek-qq-bot.service
[Unit]
Description=DeepSeek QQ Bot
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/qq-deepseek-bot
ExecStart=/opt/qq-deepseek-bot/.venv/bin/python src/main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now deepseek-qq-bot
journalctl -u deepseek-qq-bot -f
```

NapCat 在 Linux 上一般用 Docker（`mlikiowa/napcat-docker`）或官方 Shell 包，注意容器网络里 `127.0.0.1` 要换成宿主机地址。

### 6.3 Docker Compose（bot + NapCat）

项目自带 `Dockerfile` 和 `docker-compose.yml`，一条命令同时起机器人和 NapCat，适合 Windows Docker Desktop 或 Linux 服务器。

前置：Docker Engine / Docker Desktop + compose 插件，能访问 Docker Hub 和 `api.deepseek.com`。

**步骤**

1. 准备 `.env`：

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

   ```dotenv
   DEEPSEEK_API_KEY=sk-...
   WEB_TOKEN=随便设一个访问密码
   ONEBOT_ACCESS_TOKEN=给 NapCat 用的 token
   ```

2. 想用 WebUI，把 `config/config.yaml` 的 `web.enabled` 改成 `true`。容器里的 `host/port` 由 compose 环境变量覆盖成 `0.0.0.0:8080`，不用改；但**非本机绑定必须有 `WEB_TOKEN`**，否则 WebUI 拒绝启动。

3. 启动：

   ```powershell
   docker compose up -d --build
   docker compose logs -f bot
   ```

4. 登录 NapCat：浏览器打开 <http://127.0.0.1:6099>（首次的 token/二维码看 `docker compose logs napcat`），扫码登录小号；在「网络配置」新建 **WebSocket 服务器**：`0.0.0.0:3001`，token 填 `.env` 里的 `ONEBOT_ACCESS_TOKEN`，启用。

5. 机器人会自动重连，不需要严格等 NapCat 先启动；日志出现「已连接 OneBot 服务」即可。

6. WebUI：<http://127.0.0.1:8080/>，右上角填 `WEB_TOKEN`。

**卷与端口**

| 宿主机 | 容器 | 作用 |
| --- | --- | --- |
| `./config` | `/app/config` | 配置与人格 |
| `./data` | `/app/data` | SQLite 记忆 |
| `./napcat/config` | `/app/napcat/config` | NapCat 网络配置 |
| `./napcat/qq` | `/app/.config/QQ` | QQ 登录态 |
| `127.0.0.1:6099` | `6099` | NapCat WebUI |
| `127.0.0.1:8080` | `8080` | 机器人 WebUI |

**常用命令**

```powershell
docker compose ps
docker compose logs -f bot
docker compose logs -f napcat
docker compose restart bot
docker compose down
docker compose up -d --build   # 改代码后重建
```

**注意**

- bot 容器通过服务名访问协议端：compose 已设置 `ONEBOT_WS_URL=ws://napcat:3001`，不要在配置里写 `127.0.0.1`；
- NapCat 的 WS token 与 `.env` 的 `ONEBOT_ACCESS_TOKEN` 必须一致；
- 端口只绑定 `127.0.0.1`；远程访问请用 SSH 隧道或反向代理 + HTTPS；
- 拉不到 NapCat 镜像时检查网络/代理，或退回 1–5 节的手动部署；
- 容器时区已设为 `Asia/Shanghai`。

### 6.4 官方 QQ 机器人（可选，实验性）

不想用第三方协议端，可以接 QQ 机器人开放平台（合规、但能力受限）。当前适配器只处理：

- 群里 **@ 机器人** 的消息；
- **私聊**消息。

**步骤**

1. 在 [QQ 机器人开放平台](https://q.qq.com/) 创建机器人，拿到 `AppID` / `AppSecret`，配置 IP 白名单并申请群聊/私聊权限；
2. `.env`：

   ```dotenv
   OFFICIAL_APP_ID=你的AppID
   OFFICIAL_APP_SECRET=你的AppSecret
   ```

3. `config.yaml`：

   ```yaml
   official:
     enabled: true
     intents: 33554432        # GROUP_AND_C2C_EVENT
   ```

4. `python src/main.py`（不需要 NapCat）。

**限制（务必知道）**

- 群里收不到非 @ 消息，所以唤醒词、环境插话、主动发言都不会生效；官方模式下主动发言调度器会自动不启动；
- 内部 id 是 openid 的稳定哈希，日志/WebUI 里不是真实 QQ 号；
- 未实现 shard / resume / 频道（guild）消息；
- 主动消息受平台权限限制，本适配器只保证被动回复；
- Docker 部署时可只跑 bot（把 compose 里的 `depends_on: napcat` 去掉、不启动 napcat 服务）。

## 7. 反向 WebSocket（可选）

默认是**正向 WS**：机器人主动连 NapCat（`onebot.mode: forward`）。

如果 NapCat 在另一台机器 / 容器里，不方便让机器人主动连，可以改成**反向 WS**：机器人监听端口，NapCat 主动连过来。

**配置**

```yaml
onebot:
  mode: reverse
  reverse_host: 0.0.0.0
  reverse_port: 3002
  access_token_env: ONEBOT_ACCESS_TOKEN
```

`.env` 里填 `ONEBOT_ACCESS_TOKEN=一个token`（反向连接时 NapCat 用它鉴权）。

**NapCat 侧**

1. 打开 NapCat WebUI → 网络配置 → 新建 **WebSocket 客户端**；
2. URL：`ws://<机器人IP>:3002`；
3. Token：与 `ONEBOT_ACCESS_TOKEN` 一致；
4. 启用，确认 NapCat 日志显示连接成功。

**说明**

- 机器人启动日志会显示 `反向 OneBot 已监听：ws://0.0.0.0:3002`；
- 收到连接后会校验 `Authorization: Bearer <token>`，不一致直接关闭；
- `X-Self-ID` 头会被用来记录机器人 QQ 号；
- 支持 NapCat 断线重连（重连后会替换旧连接）；
- 注意把 3002 端口暴露给 NapCat 所在机器（防火墙/容器端口映射）；
- 不要同时开正向和反向，`mode` 二选一。

## 8. 排错表

| 现象 | 可能原因 | 解决 |
| --- | --- | --- |
| 启动就退出，提示没有 API Key | `.env` 没建 / 变量名写错 | 确认项目根目录有 `.env`，字段名 `DEEPSEEK_API_KEY` |
| `FileNotFoundError: config/config.yaml` | 工作目录不对 | 在项目根目录运行，或用 `start.bat` |
| 连接超时 / WinError 10061 | NapCat 没开 WS 服务，或端口不对 | 看 NapCat 网络配置；`Test-NetConnection` |
| 反复重连，日志 `HTTP 403` | token 不一致 | `.env` 的 `ONEBOT_ACCESS_TOKEN` 与 NapCat 完全一致 |
| 能连上但收不到消息 | NapCat 没登录成功 / 收消息被关 | 用 QQ 给机器人发消息，看 NapCat 日志是否有事件 |
| 回复 `HTTP 401` | DeepSeek key 无效 | 检查 key；确认账户有余额 |
| 回复 `HTTP 402` / 余额不足 | 没充值 | DeepSeek 平台充值 |
| 回复 `HTTP 429` | 限流 | 降低频率，或稍等重试（客户端已自动重试 2 次） |
| 模型回复"（想说的太多，卡住了…）" | 工具调用两轮还没出结果 | 检查工具返回值；或关掉 `enable_tools` |
| 群里 @ 了但没反应 | 群号被 `whitelist_groups` 排除，或被限流 | 看日志触发原因；`log_level: DEBUG` |
| 群里每条都回 | `ambient_chance` 太高，或唤醒词过短（如「鱼」） | 降低概率/改唤醒词 |
| 回复带 `**`、`#` | 模型输出了 Markdown | 本项目会自动清洗；若仍出现，检查是否被截断 |
| 回复被拆成很多条 | `split_chars` 太小 | 调大 `split_chars`（160~300） |
| 回复太慢 | 上下文太长 / 模型选错 | 调小 `token_budget`；确认没开 `reasoner` |
| 图片没被理解 | `vision.enabled` 未开 / 未配 key | 看启动日志的「图片理解」；检查 `VISION_API_KEY` |
| 图片理解 401 / 404 | `base_url` 或 `model` 不对 | 确认 base_url 以 `/v1` 结尾、模型名与平台一致 |
| 图片理解超时 | 图片太大或网络慢 | 调小 `max_image_bytes`、调大 `timeout` |
| WebUI 打开 401 | token 没填 / 填错 | 右上角填 `.env` 里的 `WEB_TOKEN` |
| WebUI 打不开 | 未开启 / 端口被占用 / 拒绝启动 | 看日志 `WebUI`；改 `web.port`；非本机必须配 token |
| 机器人突然自己说话 | 主动发言开启 | 检查 `chat.proactive.enabled` 和 `groups`；不需要就关掉 |
| `docker compose` 报 env file not found | 没有 `.env` | `Copy-Item .env.example .env` 后重试 |
| 容器内日志 `连不上 ws://napcat:3001` | NapCat 未就绪 / 没开 WS | 等 NapCat 登录并配置 WS，bot 会自动重连 |
| 容器启动了但 WebUI 打不开 | 没配 `WEB_TOKEN` / `web.enabled` 为 false | 看 `docker compose logs bot`；补 token、改配置后重启 |
| 用量统计不涨 / 打不开 `metrics.db` | 目录权限 / 磁盘满 | 检查 `data/` 写权限与磁盘；`metrics.enabled: false` 可临时关闭 |
| 官方接口 401 / 获取 token 失败 | AppID/Secret 错、IP 不在白名单 | 核对 `.env` 与开放平台配置；看日志里的 HTTP 响应 |
| 官方接口收不到消息 | 没申请群聊权限 / intents 不对 | 开放平台确认权限与沙箱群；intents 用 `33554432` |
| 官方接口发送报“未知群/用户” | 进程重启后还没收到过消息 | 先让群友 @ 一次 / 私聊一次，映射建立后才能发 |
| 反向 WS 连不上 | 端口没映射 / token 不一致 / mode 没改 | 检查 `onebot.mode: reverse`、3002 端口、`ONEBOT_ACCESS_TOKEN` |
| 启动提示“已有一个实例在运行” | 同一 data 目录已跑了一个 bot | 停掉旧进程；锁由系统在进程退出时自动释放 |
| `napcat` 容器起不来 | 镜像架构 / UID 权限 / 网络 | `docker compose logs napcat`，检查镜像与 `NAPCAT_UID/GID` |
| 聊几句就"忘了" | 摘要/记忆异常 | 看日志有没有「已生成摘要」；检查 `data/bot.db` 权限 |
| 中文乱码（Windows 终端） | 控制台编码 | 用 `start.bat`（已设 `chcp 65001`），或 `chcp 65001` |
| 机器人被冻结/限制 | 协议端风控 | 停用、换小号、降低频率、别群发 |
| `sqlite3.OperationalError: database is locked` | 同一个库被多个进程打开 | 确保只跑一个实例 |
| 端口 3001 被占用 | 别的程序在用 | 换端口，同步改 `ws_url` 和 NapCat |

调试建议：把 `config.yaml` 的 `log_level` 改成 `DEBUG`，日志会打出每条被跳过的消息及其原因，是调触发策略最快的办法。

## 9. 安全与合规提醒

1. **用小号**。第三方协议端不是官方接口，封号没有申诉渠道。
2. **控制频率**。默认冷却 6 秒、每分钟 8 条已经是偏保守的值，不要为了"活跃"调到很高。
3. **不要群发、不要营销、不要骚扰**。这既违反群规，也最容易触发风控。
4. **API Key 只放 `.env`**，不要提交 git、不要发群、不要截图。
5. **聊天记录本地存储**，但上下文会发给 DeepSeek。部署在他人机器上时请说明。
6. **内容安全**：提示词边界 + `blocked_words` 只是基础保险，正式场景请加输出审核。
7. **想长期做**：走 [QQ 机器人开放平台](https://q.qq.com/)，合规、稳定，但需要主体资质和群聊能力申请。
