# 从本机到云端：一个 QQ 机器人（NapCat + Python）的完整部署实录

> 这是一份**真实踩坑记录**，不是官方文档的复述。文中的 IP、令牌、QQ 号都已脱敏，照着换掉就能用。
> 适用场景：把本地跑得好好的 QQ 机器人（NapCat 协议端 + Python 业务层）迁到一台常开的 Linux 云服务器上，
> 并实现「本机改代码 → 自动同步到云端」。

---

## 一、为什么要上云

本机跑的时候是这样的：QQ 客户端 + NapCat（注入 QQ 的协议端）+ Python bot，全在你自己的电脑上。

问题很明显：

| 本机 | 后果 |
| --- | --- |
| 一关机 / 一睡眠 | 机器人立刻下线：不回消息、定时提醒不发、主动关心不触发 |
| 断网 / 重启 | NapCat 掉线，QQ 要重新扫码 |
| 挂机一天 | 电脑得一直开着，费电、风扇吵 |
| 换电脑 | 数据（记忆、表情包）都在旧机器上 |

所以最终方案是：**业务跑在云服务器上，本机只负责写代码**。

## 二、整体架构

```
┌──────────────── 云服务器（Ubuntu 24.04）────────────────┐
│                                                        │
│   ┌──────────────┐        ws://napcat:3001   ┌───────┐ │
│   │  NapCat 容器  │ ◀─────────────────────── │ bot   │ │
│   │  qq-napcat    │                         │ 容器  │ │
│   │  (QQ 登录)    │        ┌──────────────┐  │ qq-bot│ │
│   │  :6099 WebUI  │        │ /opt/qq-     │  │ :8080 │ │
│   └──────┬───────┘        │ deepseek-bot │  └───┬───┘ │
│          │                │  ├─ code/     │      │     │
│          │                │  ├─ config/   │      │     │
│          │                │  └─ data/     │      │     │
│          │                └──────────────┘      │     │
└──────────┼─────────────────────────────────────┼─────┘
           │ 手机 QQ 扫码                            │ HTTP 8080
           ▼                                         ▼
      机器人 QQ 账号                          浏览器看成绩单 / 管理页

本机（Windows）── git push ──▶ Gitee 私有仓库 ──每 5 分钟 git pull──▶ 云端
```

组件职责：

| 组件 | 作用 |
| --- | --- |
| **NapCat** | 注入 QQ 客户端，把 QQ 消息转成 OneBot v11 协议（WebSocket），同时提供网页管理/扫码 |
| **bot（本项目）** | Python 实现：接 OneBot 消息 → 调用大模型 → 回复；记忆、提醒、群报、成绩单图片都在这里 |
| **Gitee 私有仓库** | 代码中转站：本机 push，云端 pull，实现改代码自动上线 |
| **大模型 API** | 云端调 DeepSeek API（需要服务器能访问外网） |

## 三、买服务器

| 项目 | 推荐 | 说明 |
| --- | --- | --- |
| 厂商 | 腾讯云 / 阿里云轻量应用服务器 | 国内节点，访问 QQ 和 API 都稳 |
| 系统 | **Ubuntu 22.04 / 24.04** | 本文以 Ubuntu 24.04 为例 |
| 配置 | 2 核 4G，系统盘 40G+ | 2 核 2G 能跑但紧；NapCat + QQ 是内存大户 |
| 带宽 | 3~5 Mbps 足够 | 机器人不发大文件 |
| 安全组 | 放行 22（SSH）、6099（NapCat 网页）、8080（bot 网页） | 8080 建议只对自己 IP 开放，或配 token |

> 成本参考：2 核 4G 轻量，新用户活动价常见 50~100 元/月。
> 实测这个 bot 的常驻内存：NapCat 容器约 300MB，bot 容器约 150MB，CPU 基本空闲。

## 四、服务器初始化

### 1. 登录服务器

用云厂商自带的**网页终端**最省事（腾讯云轻量叫 OrcaTerm，阿里云叫远程连接），
跳过 SSH 配置，适合第一次部署。

### 2. 装基础环境

```bash
sudo apt-get update -y
sudo apt-get install -y python3-venv python3-pip docker.io git curl unzip
sudo systemctl enable --now docker
python3 --version     # Ubuntu 24.04 自带 3.12
docker --version
```

### 3. 配 Docker 镜像加速（重要，不然拉镜像很慢）

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com"] }
EOF
sudo systemctl restart docker
```

（阿里云对应 `https://<你的ID>.mirror.aliyuncs.com`，华为云 `https://mirrors.huaweicloud.com`。）

### 4. 防火墙放行端口

在云控制台的「防火墙 / 安全组」里加两条 **TCP** 入站规则：

- `6099`：NapCat 网页（扫码登录、看连接状态）
- `8080`：bot 自己的网页（成绩单、管理页）

来源建议填自己的 IP；图省事可以先 0.0.0.0/0，但务必给 WebUI 配 token。

## 五、部署 NapCat（QQ 协议端）

NapCat 官方主要发 Windows 版，Linux 上最省事的是**社区 Docker 镜像**，镜像里自带 QQ。

```bash
# 配置目录（挂载出来，方便改配置、留登录态）
mkdir -p /home/ubuntu/napcat/config /home/ubuntu/napcat/qq

# 启动
sudo docker run -d --name qq-napcat --restart unless-stopped \
  -p 3001:3001 \
  -p 6099:6099 \
  -v /home/ubuntu/napcat/config:/app/napcat/config \
  -v /home/ubuntu/napcat/qq:/app/.config/QQ \
  mlikiowa/napcat-docker:latest
```

### 1. 扫码登录 QQ

```bash
sudo docker logs -f qq-napcat
```

日志里会打印一张 **ASCII 二维码**。⚠️ **终端里的二维码经常扫不出来**（分辨率/字体问题），
两个可靠的替代办法：

```bash
# 办法 A：把二维码图片抠出来，下载到手机扫
sudo docker cp qq-napcat:/app/napcat/cache/qrcode.png /home/ubuntu/qrcode.png
# 然后用云控制台的「文件管理」下载这个 png，手机 QQ 从相册选图扫码

# 办法 B：重启容器刷新二维码，多试几次
sudo docker restart qq-napcat && sleep 10
sudo docker logs qq-napcat 2>&1 | tail -30
```

登录成功后日志会出现 `账号 1234567890 登录成功` 之类的字样。

### 2. 配 OneBot WebSocket（3001）——最容易漏的一步

NapCat 默认**不开** OneBot WebSocket 服务，配置文件里的 `websocketServers` 是空的。
不开的话，bot 会一直报 `Connect call failed ('172.18.0.3', 3001)`。

配置文件在容器内：`/app/napcat/config/onebot11_<QQ号>.json`（挂载后对应宿主机 `napcat/config/`）。
用编辑或直接写入：

```json
{
  "network": {
    "websocketServers": [
      {
        "name": "bot",
        "enable": true,
        "host": "0.0.0.0",
        "port": 3001,
        "messagePostFormat": "array",
        "reportSelfMessage": false,
        "token": "",
        "debug": false
      }
    ]
  }
}
```

改完重启容器：

```bash
sudo docker restart qq-napcat
sudo docker logs qq-napcat 2>&1 | tail -10
# 看到 "WebSocket服务: 0.0.0.0:3001，已启动" 就对了
```

> 注意 `host` 在容器里要写 `0.0.0.0`（容器内的 127.0.0.1 只有容器自己能访问），
> 宿主机映射 `-p 3001:3001` 后，bot 容器就可以用 `napcat:3001` 或 `宿主IP:3001` 连。

## 六、部署 bot（Python）

### 1. 代码上传（第一次）

两种方式，选一个：

**方式 A：控制台「文件管理」上传压缩包**（适合不想配 SSH 的情况）

```bash
cd /home/ubuntu
tar -xzf bot-code.tar.gz -C qq-deepseek-bot    # 打包时只包含代码，不含 data/
```

**方式 B：git clone**（推荐，后文有自动同步）

```bash
sudo mkdir -p /opt/qq-deepseek-bot
sudo git clone https://oauth2:<你的令牌>@gitee.com/<你的用户名>/qq-deepseek-bot.git /opt/qq-deepseek-bot/code
```

### 2. 装 Python 依赖

```bash
cd /home/ubuntu/qq-deepseek-bot      # 或 /opt/qq-deepseek-bot/code
python3 -m venv .venv
.venv/bin/pip install -U pip -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> 用清华 PyPI 镜像，几十个依赖 1 分钟内装完；直连 PyPI 可能要好几分钟。

### 3. 配置 `.env` 和 `config/config.yaml`

`.env`（不要提交到仓库）：

```ini
DEEPSEEK_API_KEY=sk-xxxxxxxx
WEB_TOKEN=自己设一个网页访问密码
```

`config/config.yaml` 里跟云端相关的几个点：

```yaml
onebot:
  ws_url: ws://napcat:3001      # 同机容器网络用服务名；不同机就填对方 IP
  access_token: ""              # 如果 NapCat 配了 token 就对应填

web:
  host: 0.0.0.0                 # 允许外部访问管理页（必须配 WEB_TOKEN！）
  port: 8080

memory:
  db_path: data/bot.db          # 容器内路径，挂载到宿主机持久化
```

### 4. 起 bot 容器

最省事：**复用现成的镜像**（如果之前构建过），只把配置和数据挂出来：

```bash
sudo docker run -d --name qq-bot --restart unless-stopped \
  --network bridge \
  -p 8080:8080 \
  -v /opt/qq-deepseek-bot/config:/app/config \
  -v /opt/qq-deepseek-bot/data:/app/data \
  deepseek-qq-bot
```

如果镜像还没构建，先写 `Dockerfile`：

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
COPY src/ ./src/
COPY scripts/ ./scripts/
CMD ["python", "src/main.py"]
```

```bash
cd /opt/qq-deepseek-bot/code && sudo docker build -t deepseek-qq-bot .
```

> 容器之间要能互相解析服务名（`napcat:3001`），最简单的做法是两个容器都用默认 bridge，
> 或者自建 network：`docker network create botnet`，然后两个容器 `--network botnet`。

### 5. 验证

```bash
sudo docker ps                          # 两个容器都是 Up
sudo docker logs qq-bot 2>&1 | tail -20 # 关键日志：已连接 OneBot 服务 / 机器人账号
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/   # 200
```

在群里 @ 机器人发一句话，能正常回复就通了。

## 七、代码同步：本机改完自动上云

这是整套方案里最爽的一环：**本机只管写代码，云端自动更新**。

### 1. 建一个 Gitee 私有仓库

- 新建仓库 → 私有 → 不要勾选 README 初始化
- 生成私人令牌（设置 → 私人令牌 → 勾选 `projects`）

### 2. 本机一键推送

`scripts/push_to_git.ps1`（Windows PowerShell）：

```powershell
# 关键点：本机全局 git 可能配了代理、Windows schannel 又可能报错，
# 所以统一用 -c 参数跳过代理 + 换 OpenSSL 后端
$gitArgs = @("-c","http.proxy=","-c","https.proxy=","-c","http.sslBackend=openssl")
git @gitArgs push -u origin master
```

### 3. 云端一键拉取

`scripts/cloud_git_pull.sh`：

```bash
#!/bin/bash
set -e
REPO_DIR="/opt/qq-deepseek-bot/code"
CONTAINER="qq-bot"

cd "$REPO_DIR"
BEFORE=$(git rev-parse HEAD)
git fetch origin master
git reset --hard origin/master
AFTER=$(git rev-parse HEAD)

# 代码没变就不重启，避免无谓掉线
[ "$BEFORE" = "$AFTER" ] && { echo "代码没有变化"; exit 0; }

echo "更新：$BEFORE -> $AFTER"
sudo docker cp "$REPO_DIR/src/." "$CONTAINER:/app/src/"
sudo docker restart "$CONTAINER"
sleep 6
sudo docker logs "$CONTAINER" 2>&1 | tail -20
```

### 4. 定时自动拉取

```bash
crontab -e
# 选 nano（直接回车），最后加一行：
*/5 * * * * bash /opt/qq-deepseek-bot/code/scripts/cloud_git_pull.sh >> /home/ubuntu/git_pull.log 2>&1
# Ctrl+O 回车保存，Ctrl+X 退出
crontab -l   # 确认写入
```

之后流程就是：

```
改代码 → 跑测试 → git commit → git push
        → 云端 5 分钟内自动 pull → 更新容器 → 重启 → 生效
```

## 八、踩坑清单（这一节最值钱）

### 1. 本机 git 配了一个没运行的代理

```
fatal: unable to access 'https://gitee.com/...': Failed to connect ... over proxy 127.0.0.1
```

本机全局 git 配置了 `http.proxy=127.0.0.1:7890`，但那个代理软件没开。
解决：命令里用 `-c http.proxy=` `-c https.proxy=` 临时清空（不要随便改全局配置，可能影响别的工具）。

### 2. Windows schannel 报「安全包中没有可用的凭证」

```
schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)
```

Git for Windows 默认用 schannel 做 TLS，在部分环境下拿不到凭证。
解决：`git -c http.sslBackend=openssl ...` 换成 OpenSSL 后端。

### 3. SSH 连服务器，连到的却是另一台机器

现象：公钥明明加对了、指纹也匹配、sshd 配置正常，就是 `Permission denied`。
一查 host key 指纹和服务器上的完全对不上，SSH banner 还从 Ubuntu 的 8.9 变成 7.4——
说明**出口网络把 22 端口的流量劫持/重定向了**。

解决：别死磕 SSH，直接用云控制台的**网页终端**（OrcaTerm）操作；代码同步改用 git（HTTPS）。

### 4. 终端里的 QR 二维码扫不出来

NapCat 在日志里打的 ASCII 二维码，手机几乎扫不到。
解决：`docker cp` 把 `qrcode.png` 拷出来下载到手机相册扫码，或从 6099 WebUI 里扫。

### 5. NapCat 的 OneBot 服务默认是关的

`websocketServers: []` → bot 一直 `Connect call failed (..., 3001)`。
解决：按第五节编辑 `onebot11_<QQ号>.json`，把 3001 开出来并重启 NapCat。

### 6. 同一个 QQ 号两地同时登录，互相踢

本机和云端都登录同一个机器人 QQ 时，会出现
`当前账号(1234567890)已登录，无法重复登录`，表现就是随机掉线、有时不回消息。
解决：**同一时间只让一处登录**。迁移到云端后，把本机 QQ / NapCat / bot 全部关掉。

### 7. FastAPI 请求体模型写在函数里 → 422

代码层的小坑：把 `class Request(BaseModel)` 定义在 `create_app()` 函数内部时，
FastAPI 会把它当成 query 参数，POST 直接 422。
解决：请求体模型放到**模块级**。

### 8. 拉镜像 / 装依赖慢

- Docker：配腾讯云内网镜像加速 `mirror.ccs.tencentyun.com`；
- pip：用清华源 `-i https://pypi.tuna.tsinghua.edu.cn/simple`。

## 九、运维速查

```bash
# 看容器
sudo docker ps
sudo docker logs qq-bot --tail 50
sudo docker logs qq-napcat --tail 50

# 重启
sudo docker restart qq-bot
sudo docker restart qq-napcat

# 进容器
sudo docker exec -it qq-bot sh

# 手动更新代码
bash /opt/qq-deepseek-bot/code/scripts/cloud_git_pull.sh

# 看自动更新日志
tail -30 /home/ubuntu/git_pull.log

# 端口占用检查
ss -ltnp | grep -E ':3001|:8080|:6099'
```

### 常见症状对照表

| 症状 | 先查什么 |
| --- | --- |
| 群里 @ 没反应 | `docker ps` 两个容器是否 Up；`docker logs qq-bot` 有没有「已连接 OneBot」 |
| 「已连接」后又断 | NapCat 是否掉线（QQ 被踢/掉登录）；`docker logs qq-napcat` |
| 8080 打不开 | 云防火墙是否放行；`web.host` 是否 0.0.0.0；`WEB_TOKEN` 是否配 |
| 更新代码不生效 | `git_pull.log` 是否在跑；容器是否重启成功 |
| 扫码登录失败 | 换二维码图片方式；确认没有别处登录同一账号 |

## 十、最终效果

- 本机关机、断网都不影响机器人：它在云上 7×24 跑着；
- 本机只负责写代码 + 跑测试，`git push` 之后 5 分钟内云端自动更新；
- 数据（聊天记忆、表情包、画像）都在云服务器的 `data/` 目录里，容器重启不丢；
- 一个 2 核 4G 的轻量服务器足够，日常内存占用 500MB 左右。
