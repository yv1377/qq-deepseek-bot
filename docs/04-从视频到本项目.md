# 从视频到本项目：路线对照与改造指南

你看到的视频是「3 分钟把 DeepSeek 接进 QQ 群」那类教程，核心是**协议端 + 适配器 + 模型 API** 三件套。本项目做的是同一件事，但把中间那层换成了可读、可改的自研内核。

---

## 1. 视频里的典型路线

绝大多数"DeepSeek 接 QQ"教程，本质都是这三步：

```
QQ 小号
  └─ 第三方协议端（NapCat / LLOneBot / Lagrange）
        └─ OneBot v11
              └─ 现成的机器人框架或适配项目（AstrBot / NoneBot 插件 / 自写脚本）
                    └─ DeepSeek / 其他大模型 API
```

常见做法有两种：

- **一键项目**：AstrBot、各类 "DeepSeek-QQ-Bot" 仓库，填 key、扫码、开跑；
- **框架 + 插件**：NoneBot2 装 OneBot 适配器，再装一个 LLM 插件。

它们的优点是快，缺点是：**行为是别人设计好的**，想改"什么时候说话、怎么记上下文、怎么洗输出"，得读框架源码。

---

## 2. 本项目的取舍

| 维度 | 视频/一键项目 | 本项目 |
| --- | --- | --- |
| 上手速度 | 几分钟 | 半小时（装依赖、配 NapCat） |
| 可改性 | 改配置 / 改插件 | 每层都能改，代码量约 1500 行 |
| 群聊策略 | 一般是"@ 就回" | @ / 回复 / 唤醒词 / 概率插话 + 冷却 + 限流 |
| 上下文 | 简单拼接历史 | 五段式 + token 预算 + 群聊背景分角色 |
| 记忆 | 可能有 / 可能无 | 会话记忆 + 后台摘要 + 群背景缓存 |
| 输出适配 | 直接发 Markdown | 清洗 + 限长 + 分条 + 引用 |
| 扩展性 | 看框架 | 加工具 / 换模型 / 换协议只动一层 |

一句话：**视频给你"能跑"，本项目给你"能懂、能改"。**

---

## 3. 最短路径：只想要视频里的效果

1. 装 NapCat，登录小号，开 WebSocket 3001；
2. 本项目目录里 `pip install -r requirements.txt`；
3. `.env` 填 DeepSeek key；
4. `config.yaml` 里 `onebot.ws_url` 对上、`admin.qq` 填自己；
5. `python src/main.py`；
6. 先跑 `python scripts/smoke_test.py` 确认代码没坏；
7. 想更"活跃"就调 `ambient_chance`，想更"省"就调 `token_budget`。

不需要写代码。

## 4. 想改成自己的：五个常见方向

### 4.1 换人格

只改 `config/persona.md`，不用重启代码逻辑（重启进程生效）。见 [03-人格调教.md](03-人格调教.md)。

### 4.2 换触发规则

改 `src/policy.py::decide`。例如"只允许 @ 触发，完全不要唤醒词和插话"：

```python
reason = "at" if incoming.at_self else ""
if not reason:
    return Decision(False, "no-trigger")
```

或者"白名单里的群，每条都回"：

```python
if group_id in cfg.filter.whitelist_groups:
    reason = "whitelisted-group"
```

### 4.3 换协议端 / 官方接口

业务层只依赖两个东西：

- 进来的 `Incoming`（`onebot.py`）；
- 出去的 `send_group_text` / `send_private_text`（`chat.SenderLike`）。

换官方 QQ 机器人 SDK 时，写一个新的适配器实现这两个方法、把官方事件转成 `Incoming`，然后 `ChatService` 原样复用。

### 4.4 加工具

在 `src/tools.py` 里加 `TOOL_SPECS` 条目和 `dispatch` 分支，例如联网搜索：

```python
if name == "web_search":
    query = str(args.get("query") or "")
    return await search(query)  # 自己实现
```

再把 `config.yaml` 的 `deepseek.enable_tools` 改成 `true`。注意：工具调用会多一轮请求，延迟和成本都会上升，建议只在正经问题时开。

### 4.5 多群不同人格

当前人格是全局的。想做"群 A 是肥鱼、群 B 是别的角色"：

1. `persona` 增加一个 `group_personas: {群号: 文件路径}` 配置；
2. `ChatService` 里按群号选 persona；
3. `build_system` 传入选中的 persona 即可。

改动点集中在 `config.py` / `chat.py` / `prompt.py`，不复杂。

## 5. 视频没讲、但一定会踩的坑

1. **风控**：第三方协议端有封号风险，教程不会强调。用不重要的号，频率别高。
2. **上下文爆炸**：把整段聊天记录塞进 prompt，聊两天就贵到离谱。本项目用"摘要 + 预算裁剪"解决。
3. **每条都回**：最容易被踢群的原因。默认应该沉默。
4. **Markdown**：QQ 不渲染，`**加粗**` 会原样显示，必须清洗。
5. **重连与去重**：NapCat 重启后可能重放事件，没有去重会重复回复。
6. **成本**：没有摘要和预算，一天几十块很正常。
7. **群规**：进群前问群主，公开说明是机器人。
8. **多实例**：同一个 QQ 号别开两个进程，会抢连接、抢数据库。

## 6. 建议的学习顺序

如果你是想**学原理**而不是只要一个能跑的 bot：

1. 先读 `src/onebot.py`：理解 QQ 消息怎么变成 Python 对象；
2. 再读 `src/policy.py`：理解"什么时候该闭嘴"；
3. 然后 `src/prompt.py` + `src/memory.py`：理解上下文和记忆；
4. 最后 `src/chat.py`：看它们怎么串起来；
5. 跑 `scripts/smoke_test.py`，改一行代码看哪个检查挂了——比读十遍代码有用。
