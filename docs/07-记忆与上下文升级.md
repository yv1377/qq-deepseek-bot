## 1. 文章里的六层机制

| 文章的机制 | 一句话概括 | 我们的情况 |
| --- | --- | --- |
| `roster.js`：身份 | `Bot = 长期身份 + 执行会话 + 持久化状态`，身份与底层模型解耦 | ✅ 早就有：人格卡 + 多群人格，与模型无关 |
| `prompt.js`：角色 | 用 system prompt 的 `bot-identity` 段告诉模型"你是谁、要守什么规矩" | ✅ 早就有：`config/persona-*.md` |
| `tools.js` / `groups.js`：协作 | 注册明确的工具，群聊串行发言、避免基于旧信息互相冲突 | ✅ 部分有：群/私聊按 session 串行、工具调用最多两轮 |
| `handoffs.js`：任务闭环 | 上下级任务记录、结果回传，避免"每个人都做了，事情没闭环" | ⚠️ **本次新增**：待办/承诺闭环 |
| `parts.js`：上下文管家 | 上下文到 ~80% 先判断任务是否告一段落，写 Checkpoint（进展/决定/未完成/关键原话）再压缩 | ⚠️ **本次新增**：结构化检查点 + 水位触发 |
| `memory.js`：长期记忆 | 记忆独立存放、带来源与日期、每轮对话后整理、原文可检索（FTS5 索引） | ⚠️ **本次新增**：记忆管家 + 原文归档 + `recall_chat` |
| `schedules.js`：定时唤醒 | 定时任务绑定 session，换 Session 时迁移过去 | 🔶 已有主动发言调度器，暂不改 |
| 缓存成本 | 「Session 建立时固定一份记忆内容，尽量保持系统提示词前缀稳定」以命中模型缓存 | ⚠️ **本次新增**：system 前缀去掉动态时间 |

我们不是多 Bot 团队，所以没有照搬 `create_bot` / `message_bot` 那一套。
真正搬过来的是**「长期记忆 + 上下文检查点 + 任务闭环」**这三件事——
它们才是一个群友 bot"越聊越聪明"的地基。

## 2. 本次改动

### 2.1 上下文管家：从"按条数截断"到"结构化检查点"

- 触发条件不再只看消息条数：
  `chat.memory.summary_trigger`（默认 20 条）**或** 活动消息估算 token ≥
  `chat.memory.token_budget × summary_ratio`（默认 3400 × 0.8）。
  聊得密、句子长时会更早做检查点，防止上下文撑爆后细节被硬截断。
- 摘要提示词改成**四节检查点**（`src/llm.py` 的 `SUMMARY_SYSTEM`）：
  `## 长期事实` / `## 未完成的事` / `## 关键原话` / `## 最近话题`。
  和文章里 Checkpoint 保留"当前进展、重要决定、未完成步骤、关键原话"是同一个思路。
- 摘要上限从 1200 字放宽到 1600 字，给「关键原话」留位置。

### 2.2 压缩 ≠ 遗忘：原文归档 + `recall_chat`

- 以前：摘要成功后直接 `DELETE` 老消息，压缩损失的细节永久消失。
- 现在：先**归档**到 `archive` 表，再删活动消息；旧 `messages` 表保持"最近对话"语义不变。
- 新增工具 `recall_chat(query)`：同时搜归档原文和当前活动消息，返回**带日期**的原话。
  模型拿不准"上次谁说过"时可以自己翻，而不是编。
- 归档保留 `chat.memory.archive_keep_days` 天（默认 30，0 = 永久），启动时自动清理过期归档。

### 2.3 记忆管家：自动整理 + 带日期 + 可去重

- 新增后台任务：每回复 `chat.memory.curate_every` 次（默认 6，0 = 关闭），
  用 `llm.consolidate()` 从最近 `curate_keep` 条对话里抽长期事实，写进 `notes`。
- 写入前和已有笔记做双向包含去重；上限 6 条/次；来源标记 `自动`，
  和工具写的 `tool`、性格培养的 `性格培养` 区分开（便于 WebUI / `/notes` 审计）。
- 注入上下文时**带上日期**：`- (10-21) 小明周五要交报告`，
  减少模型把旧事说成刚发生的（"时间是记忆的一部分"）。

### 2.4 任务闭环：待办 / 承诺不再说完就忘

- 新增 `todos` 表与三个工具：`add_todo` / `list_todos` / `finish_todo`。
- 每轮上下文注入【你还没做完 / 答应过的事】，超过 2 天的会提示"可以问问进展"。
- 主动发言的 prompt 也会带上这些待办：文章讲"让任务自己找回负责人"，
  群友场景里就是**让没说完的事自己找回对话**——低频、不追问。
- 管理员新增 `/todos` 命令；`/notes` 现在带日期。

### 2.5 缓存友好：system 前缀去掉动态时间

- 以前 `## 聊天环境` 里写着「当前时间：YYYY-MM-DD HH:MM」，
  意味着 system 前缀**每分钟都变**，线上 API 的 prefix 缓存基本命中不了。
- 现在 system 只放长期稳定内容（人格 + 规则 + 场景），时间放进消息末尾的
  「环境块」`【现在】…`；整条消息顺序也按「稳定 → 易变」重排：

  ```
  system（人格/规则） → 摘要 → 笔记 → 待办 → 历史 → 群聊背景 → 环境块 → 当前消息
  ```

  这直接对应文章里「保持系统提示词前缀稳定」那一句。
  附带效果：同一个群连续聊天时，前面的前缀能被缓存，**更便宜也更快**。

## 4. 新增配置

```yaml
chat:
  memory:
    summary_ratio: 0.8        # 上下文水位：token_budget × 该比例就做检查点（0 = 只按条数）
    archive_keep_days: 30     # 原文归档保留天数（0 = 永久）
    curate_every: 6           # 每回复 N 次后台整理一次长期记忆（0 = 关闭）
    curate_keep: 12           # 整理时回看最近多少条消息
    recall_limit: 6           # recall_chat 单次最多返回几条原话
    todos_limit: 5            # 每轮注入多少条未完成待办
```

保守调法：只想省钱、不想让模型多调用 → `curate_every: 0`；
嫌她记性太好/太爱翻旧账 → `todos_limit: 0`、`notes_limit: 3`。

## 5. 新增工具

| 工具 | 什么时候用 |
| --- | --- |
| `recall_chat(query, limit?)` | 答"上次说的那个/之前谁提过"时翻原话 |
| `add_todo(content)` | 群友托付、或她答应了要做的事 |
| `list_todos()` | 查未完成待办 |
| `finish_todo(ident)` | 待办完成收尾（编号或关键词） |

## 7. 还能继续从文章里抄的

- **多 Bot 协作**：把"查资料 / 写代码 / 审阅"拆成几个子角色，QQ 群里由主 bot 派活（工程量大，暂缓）。
- **FTS5 全文索引**：目前 `recall` 用 `LIKE` + 关键词拆分，几万条以内够快；
  数据量上来后可以给 `archive` 建 FTS5（trigram 分词，中文 3 字以上更准）。
- **权限分级**：文章强调"权限边界不只靠提示词"。我们目前只有群白/黑名单、额度与工具轮数限制，
  以后若要接写文件/发邮件这类工具，需要代码级授权而不是 prompt 自律。
- **跨 session 的定时任务迁移**：主动发言已有调度器，但"定时提醒某件事"还没做；
  做的时候要注意文章提到的坑——换会话后任务别丢在旧会话里。

### 2026-10-25 补充：人物记忆与上下文读取

- 记忆管家输出 `[群]` / `[人]` 两类；人物行格式 `QQ号|昵称|事实` 会写入 `user_notes`。
- 人物笔记按当前说话人单独注入（默认最多 8 条），会话笔记默认 8 条；最近对话 16 条、上下文预算 4000。
- 默认一条回复只发一条消息（`split_chars` 大于 `max_chars`），避免拆成多段。

### 2026-10-25 补充：碎片消息合并（增强上下文关联）

- 群聊里同一人短时间内连发短句、半句话、图片单独一条时，先等待 `chat.group.merge_window`（默认 2.5 秒），
  把这一串碎片合并成一条消息再判断和回复，避免“话没说完就接半句”。
- 以逗号/省略号结尾、长度很短、只有图片的消息都视为碎片；合并后保留最新 message_id、图片和 @ 状态。
- 如果等待期间又来了新消息，旧的那次直接放弃，由最新那条负责合并后处理，防止同一串消息回多次。

### 2026-10-25 补充：引用上下文与人物记忆

- 引用/回复某条消息时，取回被引用原文（最多 180 字）作为【引用消息】注入，帮助理解指代。
- 原始消息里的 at 段会解析出被 @ 的 QQ 号；若记忆里有对方的 `user_notes`，单独注入，
  当前说话人和被 @ 的人分开处理。
- 人物笔记由记忆管家 `[人] QQ号|昵称|事实` 行持续积累，按说话人注入。

### 2026-10-26 补充：固定记忆与合并保护

- 新增 `chat.memory.pins`：按会话置顶固定记忆（870 群已钉住「鱼姐/大肥鱼/猫姐」称呼、主人和几位常互动群友的关系），
  每次请求最先注入，不进入自动整理/合并队列，不会被覆盖。
- 笔记合并（`_distill`）现在会保留 `source=手动/固定` 的笔记，只替换自动笔记；不再整批清空。
- 870 的反应式回怼、低表情包概率、搜索梗扩展都由群级配置控制，不影响其他群。
