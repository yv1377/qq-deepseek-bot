# 26 · 联网搜索：多源并行聚合

> 这轮把联网搜索从"单源降级"升级成**像 AI 助手那样多源并查、合并去重**：
> Bing / 搜狗 / 360 / 百度 同时打，谁有结果都要，重复的合并，多源命中的标出来。

---

## 一、演进过程

| 版本 | 做法 | 问题 |
| --- | --- | --- |
| 最初 | 只查 Bing（HTML + RSS） | Bing 抽风 = 全挂 |
| 中间版 | Bing → RSS → 百度 依次降级 | 本质上还是"单源兜底"，百度经常弹验证码（实测 451ms 返回无结果） |
| **现在** | **Bing / 搜狗 / 360 / 百度 四源并行，交错合并去重** | 任何一个源挂了都不影响出结果 |

## 二、现在的实现（`src/web_search.py`）

### 1. 四源并行

```
        ┌─ Bing   ─┐
查询 ──▶├─ 搜狗   ─┤──▶ 交错合并 ──▶ URL/标题去重 ──▶ 排序 ──▶ 结果
        ├─ 360    ─┤
        └─ 百度   ─┘   （asyncio.gather，各自 8 秒超时，互不阻塞）
```

- 四个源**同时请求**，不是排队降级 → 总耗时 ≈ 最慢那个源（实测 **1.6 秒**）；
- 每个源失败/无结果只记一条日志，不影响其他源；
- 结果**交错排列**（第 1 轮各源第 1 条、第 2 轮各源第 2 条…），前几条就来自不同搜索引擎，
  不会出现"前 5 条全是一个源"的情况；
- 同 URL（忽略末尾斜杠/锚点）去重，多源命中合并成一条并在来源后标注
  `（Bing/搜狗）`，可信度一眼可见。

### 2. 日志可诊断

```
INFO  search  搜索源 Bing 成功：'xxx' 结果=5 耗时=1444ms
INFO  search  搜索源 搜狗 成功：'xxx' 结果=5 耗时=965ms
INFO  search  搜索源 360 成功：'xxx' 结果=5 耗时=1243ms
WARNING search 搜索源 百度 无结果：'xxx'（556ms）
INFO  search  搜索完成：'xxx' 合并结果=15（百度: 无结果）
INFO  search  搜索命中缓存：'xxx'
WARNING search 搜索全部失败：'xxx'（Bing: ConnectTimeout；搜狗: 无结果；…）
```

### 3. 缓存与超时

- 相同查询 **10 分钟内**走内存缓存（上限 200 条，FIFO）；
- 单源超时 **8 秒**，失败源不拖累整体；
- 过滤搜索站自己的导航/聚合链接（`/link?` 之类相对链接会补全域名后保留）。

### 4. 兼容旧接口

`parse_html_results` / `parse_baidu_results` / `parse_results` 保留；
新增 `parse_sogou_items` / `parse_so360_items` / `parse_bing_items`（结构化条目）。

## 三、实测

```
四源并行：总耗时 1.7s，Bing 5 条 + 搜狗 5 条 + 360 5 条 → 合并 15 条
百度：触发验证码 → 被识别为"无结果"，不影响其他源
前 5 条来源：Bing / 搜狗 / 360（交错生效）
缓存：第二次查询 0ms 直接命中
```
